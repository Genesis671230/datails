### Architecture delivered

- **LD-4 ingestion pipeline** (`services/connectors/execution.py`): limits →
  secret → external call → blob snapshot + SHA-256 → data_ledger + run
  completion + side effects in ONE transaction. Failure semantics exactly per
  LD-4 (tested: failed call → run failed, no blob, no ledger).
- **Connector genericity (founder criterion)**: generic contracts in
  `integrations/generic_api/`; ALL Crystal knowledge in
  `integrations/crystal/`; `integrations/registry.py` is the single allowed
  touchpoint. Enforced by `test_connector_genericity.py` (import scan +
  vendor-literal scan of services). Adding connector #2 = new
  `integrations/<name>/` + one registry line.
- **Limits**: per-connector daily limit derived from `connector_runs`
  (LD-11, race-free, no reset job); global shared-key budget across all
  tenants (LD-22), config `SHARED_KEY_DAILY_BUDGET` (default 500).
- **Idempotency (LD-28)**: ASGI middleware; replay returns the original
  response (`X-Idempotent-Replay: true`); same key + different payload → 409;
  keys tenant-scoped; only 2xx recorded (DECISIONS.md).
- **Storage/secrets behind interfaces**: filesystem blobs + env-var secrets
  locally; Azure Blob/Key Vault drop in at Slice 3 with zero service changes.

### Crystal specifics

- Modes `risk_check` / `full_investigation` (Datails product terms, LD-22).
- Transport `replay` (default) serves the recorded fixtures; **`live` is
  deliberately not implemented** — it raises with an instructive message
  until the LD-6 spike confirms auth, base URL, endpoint shapes, and
  licensing. No guessed payload shapes anywhere outside the fixtures.

## When the Crystal key arrives (exact procedure)

1. Put the key in `backend/.env` (git-ignored): `CRYSTAL_API_KEY=<key>` —
   local only; in Azure it goes into Key Vault as secret `crystal-api-key`
   (LD-22), and rotation is a Key Vault version swap, zero code change.
2. Tell me the key is in place. I then run the **LD-6 spike** (timeboxed,
   max 2 days) against the real API: auth mechanics, the 3–4 starter
   endpoints and payload shapes, rate limits, pagination, error formats,
   licensing for blob persistence + report embedding, and explorer-vendor
   selection (LD-15). Findings land in `integrations/crystal/CRYSTAL_NOTES.md`.
3. From the spike: implement `_execute_live` in
   `integrations/crystal/client.py`, replace the synthetic fixtures with real
   recorded responses (file-only swap), adjust normalization to observed
   shapes, and re-run the golden tests.
4. Live acceptance check: `CRYSTAL_TRANSPORT=live` + registered connector
   with `secret_ref=CRYSTAL_API_KEY` → real call round-trips into blob +
   data_ledger + labels; CI stays on replay fixtures throughout.
