### Architecture delivered

- **Context builder** (`services/ai/context_builder.py`, LD-5): single
  assembly point; fixed inclusion priority; truncate-from-bottom against the
  per-task budget (default 8k tokens); 15-minute in-process cache keyed
  `case_id + max(updated_at across the case graph)` — any case-graph write
  invalidates; emits source refs; wallet lines carry label provenance and
  wallet_kind flags; evidence as refs only, raw payloads never inlined.
- **Model router** (`services/ai/model_router.py`, LD-24/LD-18.3): task type
  → model + context budget. GPT-4o for report drafting / finding drafts /
  research; GPT-4o-mini for summarization. Adding a model = one entry here +
  a DECISIONS.md line.
- **Task executor** (`services/ai/task_executor.py`): THE single model-call
  path. Context → route → ModelClient; every call (success AND failure)
  logged to `ai_call_log` with prompt/response hashes, tokens, latency,
  status.
- **ModelClient interface** with a deterministic mock for dev/CI; config
  refuses `AI_BACKEND=mock` outside local/dev (LD-24: production is
  Azure-hosted models only).
- **Prompts as assets** (`services/ai/prompts.py`, `services/reports/prompts.py`):
  05 §3 guardrails verbatim in system prompts (hot-wallet boundary, change-
  output ambiguity, chain-hop caution, blind-spot marking, label provenance
  citation); LD-17 reality notes in the freeze-letter and SAR instructions.
- **Learning capture** (`services/ledgers/learning.py`, LD-30): consent-gated
  at the capture point (`tenants.learning_capture_enabled`, default false);
  wired into report approval (`draft_approved`); same-transaction with the
  action; payloads carry metadata only, never raw case content.
- **Golden set** (LD-29): four fixed cases (freeze request, SAR draft, police
  intake, investigator summary) + one assistant check, asserting structural
  draft properties (draft-by-default, versioned, grounded, cited, routed) —
  run on any prompt or routing change.
